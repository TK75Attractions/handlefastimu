# 2人分のハンドル・アクセル入力（RGP/1）

ESP32 1台でMPU6050 1〜2台とADS1115の2チャンネルを読み取り、USBシリアルへRGP/1で送信します。
ペダルはP1・P2それぞれアクセル1つずつ、計2つです。ブレーキペダルは使用しません。
通信条件は **115200 bps / 8N1 / フロー制御なし** です。

## 配線

全機器のSDAをGPIO21、SCLをGPIO22に共通接続します。

| 機器 | I2Cアドレス | 設定 |
| --- | --- | --- |
| P1ハンドル MPU6050 | 0x68 | AD0をGNDへ |
| P2ハンドル MPU6050 | 0x69 | AD0を3.3Vへ |
| ADS1115 | 0x48 | ADDRをGNDへ |

| ADS1115入力 | 用途 |
| --- | --- |
| A0 | P1アクセル（従来のペダル1） |
| A1 | P2アクセル（従来のペダル2） |
| A2 | 未使用（読み取り・接続検査の対象外） |
| A3 | 未使用（読み取り・接続検査の対象外） |

- GPIO27から、**各入力に100 kΩの抵抗を1本ずつ**介してADS1115のA0・A1へ接続します（計2本）。直結しないでください。
- ESP32・IMU・ADS1115・ペダルのGNDを共通にし、I2Cは3.3Vロジック、ペダル入力は0〜3.3Vにします。
- ペダル出力は検査抵抗より十分低い出力インピーダンスを想定します。
- GPIO27のHIGH/LOWに対する電圧差で未接続を判定します。検査時以外は高インピーダンスに戻します。
- 各チャンネルの接続検査はおよそ0.3秒周期です。検査中も直前の正常値を使用します。初回接続・再接続時は、接続検査と通常電圧の取得が済むまでその入力を有効にしません。
- 検査配線がない場合や断線部がGND/電源に短絡している場合、未接続を正しく判定できません。

ハンドルのI2Cアドレスは固定し、切断時にも相手側へ切り替えません。
P1/P2は異なる種類のIMUを使用できます。WHO_AM_Iに応じてMPU6050（0x68）、MPU6500（0x70）、MPU9250（0x71）、MPU9255（0x73）、MPU6515（0x74）、MPU6886（0x19）、ICM20689（0x98）、ICM20690（0x20）のドライバーを自動選択します。I2Cアドレスと識別値は別の値です。未対応の識別値や初期化失敗は引き続き拒否します。
IMUは1台だけでも運用できます。0x68はP1、0x69はP2として扱い、接続されているIMUだけを校正・角度判定の対象にします。IMUが0台の場合は運用できません。
ピンと2ペダルそれぞれの校正電圧は `src/main.cpp` の定数で変更します。

## シリアル出力

従来のCSVと `c/C/z/Z/b/B` は廃止しました。アプリケーションから出す各行はCRC付きのRGP/1フレームです。

```text
@TYPE,SEQ,TIME[,DATA...]*CRC\n
@TEL,13,8210,-12.50,0.750,0.000,25.00,0.000,0.000*ADD8
```

TELの順序は **P1ハンドル、P1アクセル、P1ブレーキ、P2ハンドル、P2アクセル、P2ブレーキ** です。
Racing側とのRGP/1互換性のため6項目を維持し、使用しない両ブレーキ欄は常に `0.000` を送信します。
未接続側のハンドル欄は `0.00` です。直前の角度や相手側の値を流用しません。接続中のハンドルは `SYS,DEVICE,IMU,アドレス,識別値` で通知し、切断時には `EVT,IMU_LOST,アドレス` を通知します。未接続側の0は実測角度ではありません。
ハンドルは累積角度（degree、小数2桁、±3600°以内）、ペダルは0〜1（小数3桁）です。
運転者から見た時計回りを正とする取付方向で使用してください。既存実装の角度符号を維持しています。
両IMUの上下逆の取り付けに合わせて、従来の角度基準を180°ずらしています。角度0はIMUのY軸が水平で+X軸が重力方向を向く姿勢、回転軸はZ軸です。回転方向の符号は従来どおりです。
この補正は起動・ジャイロ再校正・再接続後も維持されます。未接続側のハンドル欄は引き続き0固定です。
ANGLE_ZEROは現在姿勢を任意の0°にする操作ではなく、この固定基準に対する累積回転追跡の再開始です。

ペダルは各入力固有の `clamp((V - Vmin) / (Vmax - Vmin), 0, 1)` で正規化します。
`PEDAL_CALIBRATION` の並びはADS1115のA0、A1です。
既定値はそれぞれ0〜3.3Vなので、実物のペダルに合わせて個別に調整してください。
P1・P2のアクセルは独立して送信します。

- 既定は100 Hz。SET_RATEでTELを1〜100 Hzに変更できます。遅延後にまとめて再送しません。
- 両アクセルと、1台以上の接続中IMUすべての校正値・角度基準が有効で、READYかつTEL_STREAM=1のときだけ6項目をまとめて送信します。A2・A3の接続状態は判定に使いません。
- アクセル・接続中IMUの角度が無効な場合や、IMUが0台の場合はTEL全体を停止します。未接続のハンドル欄と未使用のブレーキ欄だけを0固定にします。
- 起動最初のフレームは `SYS,0,0,HELLO,RGP,1.0,1.0.0`。すべての送信TYPEでSEQを共有します。
- 受信はLF/CRLF、最大256 bytes（CRLFの物理長は257 bytes）、途中の `@` による再同期、1秒の受信中断タイムアウトに対応します。
- CRCはCRC-16/CCITT-FALSE。対象は `@` と `*` の間の本文です。

## 起動・校正・コマンド

**起動時の自動ジャイロ校正は行いません。起動ごとにホストからCALIBRATEを実行してください。**
未測定のジャイロ校正を有効扱いにせず、接続中IMUの校正完了とフィルタ収束までWAIT_ANGLEでTELを停止します。
2つのアクセルが揃っていない場合はRECOVERINGとなるため、まず接続を復旧してください。
IMUが1台ならその1台でWAIT_ANGLEへ進み、校正後にREADYとなります。起動時に存在しないIMUのアドレスはINIT_FAILEDとして通知しません。

ホストはランダムな大文字16進16桁のSESSION_IDを生成し、次の順に接続します。
以下はCRC計算前の本文例です。実際の送信には `@`、`*CRC`、LFを付けてください。

```text
CMD,0,0,OPEN_SESSION,0123456789ABCDEF
CMD,1,0,PING
CMD,2,0,GET_STATUS
CMD,3,0,GET_CONFIG
CMD,4,0,CALIBRATE,GYRO
```

新規CMDごとにホストSEQを増やします。ACKが1秒以内に来なければ、同じSEQ・TIME・本文のフレームを最大2回再送できます。
同じSEQ・同じ本文では再実行せず、初回と同じ結果をACKします。同じSEQ・異なる本文にはFAILED,SEQ_REUSEとERRを返します。
記録は10秒経過と、その後16件の別CMD処理の両方を満たすまで保持します。
別SESSION_IDのOPEN_SESSIONで記録をリセットし、同じIDでは保持します。実行中の校正・スキャンは中断しません。

| コマンド | 引数 | 動作 |
| --- | --- | --- |
| OPEN_SESSION | SESSION_ID | 全状態でセッションを開く |
| PING | なし | OK,PONG |
| GET_STATUS | なし | STATE,ADS_OK,IMU_OK,ANGLE_LOCKED,CALIBRATED |
| GET_CONFIG | なし | TEL_RATE,IMU_RATE,TEL_STREAM,IMU_STREAM,DBG_STREAM,BETAの順に現在値 |
| ANGLE_ZERO | なし | 接続中ハンドルすべての基準取得が可能な場合にまとめて追跡を再開始 |
| SET_BETA | 0.010〜1.000 | 両フィルタに反映。小数3桁に丸めた実反映値をACK |
| SET_RATE | TEL,HZ | TEL送信周期の変更 |
| SET_STREAM | TEL,0または1 | TEL送信の停止・再開 |
| CALIBRATE | GYROまたはALL | ACCEPTEDの後、開始時に接続中のハンドルだけを順に非同期校正 |
| SCAN_I2C | なし | ACCEPTEDの後、0x08〜0x77を昇順に非同期スキャン |

IMUの任意診断ストリームとMAG校正は未実装です。該当する有効な要求にはUNSUPPORTED、不正な引数には先にINVALID_ARGを返します。
GET_CONFIGのIMU_RATE=20、IMU_STREAM=0、DBG_STREAM=0は診断ストリームの既定値を表します。DBG_STREAMはSET_STREAMで切り替えた実際の値を返します。
GET_STATUSのIMU_OKは1台以上のIMUがオンラインなら1です。ANGLE_LOCKED・CALIBRATEDは接続中の全IMUを対象に判定し、IMUが0台なら両方0です。ADS_OKは引き続き両アクセルの有効性を含みます。
OPEN_SESSION前の他CMDはNOT_READY。ANGLE_ZERO・SET_BETA・CALIBRATEはREADY/WAIT_ANGLEで受け付けます。
校正とスキャンの競合はBUSYで実行中の要求を通知します。

校正中は接続中のIMUを静止させてください。開始時に接続中のIMUをP1、P2の順に、各3秒の待機後に400サンプルを約5 ms間隔で測定します。1台の場合はその1台のみを測定します。
長い待機と測定中もシリアルCMDに応答し、受付ACKを処理開始前に返します。
ライブラリのIMU再初期化は1回約0.5秒かかります。両ハンドルの再初期化の間にも受信処理を行います。
ALLはCAL_MAG_SKIPPEDの後にGYROを行います。開始時の対象すべてが成功した場合だけORIGIN付きCAL_DONEを返し、約5秒の再収束を待ってREADYに移ります。対象IMUが途中で切断された場合は、別のIMUが残っていても校正を失敗とします。
失敗時はREQ付きERRを送り、CAL_DONEを送りません。校正と通信設定はRAMのみで、再起動で初期状態に戻ります。

アクセルの断線やIMUが0台になった場合はTELを停止してRECOVERINGへ移ります。2台から1台になっても、残ったIMUが校正済みで角度が有効なら運用を継続します。
未接続のIMUは約1秒ごとに同じアドレスへの復旧を試み、失敗ごとのログは出しません。校正済みのIMUが復旧した場合は約1.2秒再収束してREADYへ戻ります。未校正のIMUを新たに接続した場合はWAIT_ANGLEとなるため、CALIBRATEを再実行してください。
FATALでは通常のセンサー処理とTELを停止しますが、シリアル照会とI2Cスキャンは受け付けます。

PC側は6項目を一括反映し、READY離脱・TEL停止ACK・切断で両プレイヤーを即staleにしてください。
IMUの接続・切断通知も利用して、未接続側のハンドルを無効表示にしてください。TELの6項目だけでは未接続の0と実測の0°を区別できません。
最終TELから `max(3 × 1000 / TEL_RATE, 100)` msを超えた場合もstaleです。
PC受信処理はこのリポジトリには含まれないため、従来CSV受信側も同時にRGP/1へ更新する必要があります。

## ビルド・テスト

```sh
pio run
python3 test/run_tests.py
python3 test/run_imu_identity_tests.py
```

PlatformIOにFastIMU 1.2.9とAdafruit ADS1X15を依存関係として宣言しています。
通信処理はArduino非依存の `src/rgp_protocol.hpp/.cpp` に分離しています。

テストはC++11コンパイラーで実際の通信実装をコンパイルし、AddressSanitizer/UndefinedBehaviorSanitizer付きで実行します。
`test/vectors` は添付RGPフォルダーの3ファイルを変更せず収録したものです。
CRC vectors 19件とESP32受信動作60件を検証します。任意機能の実装を前提とする2件は対象外と明示します。
PC向け107件のうち有効フレームはコーデック往復を検証しますが、PC固有の不正TEL・UTF-8・stale処理を検証したとは扱いません。

追加テストでは、再送記録の保持条件、セッション更新、原子的なANGLE_ZERO、TELの送信条件、通信設定、FATAL中の応答などを確認します。
さらに実際のsetup/loopをハードウェア・角度推定の模擬実装で動かし、送信周期、2チャンネル割当、A2・A3が未接続でも動作すること、ブレーキ欄の0固定、両アクセルの切断・再接続、校正中の受信、スキャン、失敗時の通知を検証します。
IMUは2台・P1のみ・P2のみ・0台の各構成で、校正・ANGLE_ZERO・TELの割当、最後の1台の切断、追加接続・再校正も検証します。
実機への書き込み・電気的な接続検査・回転方向・実際の出力周期は、このホストテストでは確認できません。

## ペダルのノイズ除去と診断

各アクセルを独立した適応ローパスフィルターで平滑化します。静止中は約2 Hzでノイズを抑え、操作時には追従を速めます。切断・再接続や無効な測定時にはフィルターを初期化し、古い値を再利用しません。

セッション開始後に `SET_STREAM,DBG,1` を送ると、約1秒間隔でCRC付きRGPの `DBG,SUBSYSTEM,TEXT` を送信します。`SET_STREAM,DBG,0` で停止します。IMUの識別値・電源レジスタ・生の7軸値・ドライバー出力と、ADS1115のレジスタ・各アクセルの測定回数・電圧・接続検査差分を確認できます。文章はパーセントエンコードされ、長い行は複数のフレームに分割します。校正中とI2Cスキャン中は診断を保留します。診断によるI2C通信と送信量の増加を避けるため、確認後は停止してください。

旧filterブランチの `d` / `D` と4列CSVの代わりに、このRGPコマンドとDBGを利用してください。通常の2プレイヤーTEL、単独IMU運用、上下逆取付の角度基準、識別値によるドライバー選択は維持します。

## P1ハンドルだけのデバッグ入力

ゲームから `SET_INPUT_MODE,P1_STEERING` を受けた場合に限り、P1の0x68のハンドルだけを校正・角度基準・READY判定の対象とします。ADS1115・両アクセル・P2ハンドルは不要。GET_STATUSのADS_OKは実際の接続状態を維持し、不在を正常と偽りません。TELは6項目を維持しますが、この明示的なモードではP1ハンドル以外の5項目を0にします。ゲーム側がペダルとP2入力をキーボードまたは常時ペダルで補います。

`SET_INPUT_MODE,ALL` または新しいOPEN_SESSIONで通常の接続条件へ戻ります。INPUT_MODEはGET_CONFIG末尾とCONFIG_CHANGEDで通知します。変更はACK成功後に反映し、新しいTELを待ってください。未対応のホストは従来どおりALLで動きます。

GET_STATUSの成功ACK後に、接続中の各ハンドルをSYS DEVICEで、未接続の各スロットをEVT IMU_LOST,0x68/0x69で通知します。ゲームが起動時通知を逃してもP1/P2を特定できるようにする拡張です。

`python3 test/run_tests.py`には、P1のみ・ADSなし・ペダルなしでの起動、モード交渉、実際の校正処理、TELの割当、未使用P2の追加、P1切断と復旧、通常モード復帰、新セッションの通常条件復帰を追加しています。ハードウェアと角度推定はテスト用の代替実装であり、実ESP32への書き込み・操作試験とは区別します。
